# Coverage-Guided Property-Based Testing for Racket

A prototype library that extends [rackcheck](https://github.com/Bogdanp/rackcheck)
with coverage-guided feedback from [errortrace](https://docs.racket-lang.org/errortrace/).

## What It Does

Standard property-based testing generates inputs randomly — it has no
knowledge of the code being tested. Coverage-guided testing adds a feedback
loop: inputs that trigger new code coverage are saved and used to generate
future inputs via mutation. This helps the system explore hard-to-reach
code paths that random generation would miss.

## How It Differs from Ordinary rackcheck

| Feature | rackcheck | coverage-guided-testing |
|---------|-----------|------------------------|
| Input generation | Random from generators | Random + mutation of interesting inputs |
| Coverage feedback | None | errortrace execution counts |
| Corpus | None | Maintained across iterations |
| Bug finding | Relies on probability | Actively explores new code paths |
| Shrinking | Integrated shrink trees | Shrink trees + type-aware fallback |

## Quick Start

```racket
#lang racket

(require coverage-guided-testing)

;; Define your property (same syntax as rackcheck)
(define-property my-prop
  ([x (gen:integer-in -1000 1000)])
  (let ([f (dynamic-require "my-module.rkt" 'my-function)])
    (f x)
    #t))

;; Run with coverage guidance
(define result
  (check-guided my-prop
    #:config (make-guided-config
               #:max-iterations 5000
               #:seed 42
               #:verbose? #t)
    #:target "my-module.rkt"))

;; Inspect results
(print-guided-result result)
```

## How Guidance Works

1. **Instrument**: The target module is loaded with errortrace's compile
   handler, which inserts execution counters at every expression.

2. **Generate**: Initial inputs come from rackcheck generators (same as
   normal property-based testing).

3. **Execute & Measure**: Each test input is run, and coverage is
   measured by snapshotting execution counts before and after.

4. **Evaluate**: If the input triggered new coverage (or a novel
   combination of coverage), it's added to the corpus.

5. **Mutate**: Future inputs are generated by mutating corpus entries
   (type-aware mutation) or fresh generation from rackcheck.

6. **Shrink**: When a failure is found, the input is minimized using
   rackcheck's shrink trees (for fresh inputs) or type-aware shrinking
   (for mutated inputs).

## API Reference

### Configuration

```racket
(make-guided-config
  #:max-iterations 10000    ; maximum test iterations
  #:max-time-ms 30000       ; timeout in milliseconds
  #:population-size 100     ; initial population size
  #:mutation-rate 0.5       ; probability of mutation vs fresh generation
  #:seed 42                 ; RNG seed for reproducibility
  #:verbose? #f)            ; print progress to stderr
```

### Running Guided Checks

```racket
(check-guided property
  #:config guided-config
  #:target "path/to/target.rkt")
```

### Inspecting Results

```racket
(guided-result-status res)          ; 'passed, 'falsified, or 'timed-out
(guided-result-counterexample res)  ; the failing input (list of args)
(guided-result-shrunk res)          ; minimized failing input
(guided-result-exception res)       ; the exception, if any
(guided-result-iterations res)      ; number of tests run
(guided-result-corpus res)          ; the corpus of interesting inputs
(guided-result-seed res)            ; the RNG seed used
(corpus-size corpus)                ; number of corpus entries
(corpus-entries corpus)             ; list of corpus-entry structs
```

### Replay

```racket
(replay-input property args)  ; replay a specific input
```

### rackunit Integration

```racket
(check-guided-property my-prop
  #:config (make-guided-config #:seed 42)
  #:target "target.rkt")
```

## Known Limitations

- errortrace state is global and cumulative within a process
- Corpus lives in memory only (no persistence)
- Struct values cannot be mutated generically
- Mutations may produce out-of-range values for bounded generators
- Best results when the target module is small and focused
